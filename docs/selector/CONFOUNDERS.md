# 每个 selector 实验的 BEFORE 必须回答的八条

不是通用清单。**每一条都对应本项目真实付过代价的一次事故** —— 泛泛的"注意混淆变量"会被跳过,
带事故编号的不会。新实验的预注册里逐条写"本轮如何排除",写不出来的那条就是这次的风险。

分级判读由 `evidence_rag.evaluation.acceptance.classify` 执行,不靠人记(见 §二)。

---

**1. 两臂的候选池是不是同一个?**
事故:`f63e905` —— 索引缓存跨语料复用,产出了一整份无效认证。
2026-08-09 又一次:`d5f7908` 把 `k1`/`b` 折进嵌套 dict,同一个索引算出不同 `index_signature`,
job 18235971 为此烧掉 5h19m。
**检查:** 两臂的 `index_signature` 与语料快照 sha256 逐字相同;不同就先证明等价再比
(`scripts/verify_legacy_index_identity.py` 是做这件事的先例)。

**2. 基线是不是读者以为的那个?**
事故:E2 的 gate-off **不是 TopK** —— 它跑的是 corroboration 重排、只关掉了丢弃闸门。
S1 的 −11.2pp 只归功给闸门。而另一条线的表里 TopK harm 是 91.77%,与本线的 68.0% 不是同一个基线。
**检查:** 在 BEFORE 里写死基线臂的**选择器名与参数**,不写"TopK"这种口语标签。
需要真 TopK 就用 `scripts/topk_baseline.py` 从同一个池合成。

**3. 两个指标的 n 是不是同一批题?**
事故:S8 的 harm n=1479、recall n=1848 —— harm 只在窗口内有孪生的题上有定义。
**检查:** 每个指标单独报 n;**不同 n 的 delta 不得相加**,也不得说成"同一批题上的两个效应"。

**4. 变的是能力,还是测量形式?**
事故:S7 —— 同一个模型换一句 hypothesis 措辞,关键指标 19% → 54%(2.8×);
换记账口径 19% → 70%(3.7×)。**换措辞和换算法比换模型影响还大。**
**检查:** hypothesis 模板、标签空间、argmax 记账方式在两臂间逐字相同,并写进 manifest。

**5. 隔离探针的结论,能不能外推到真实池?**
事故:S6 —— 8B+解耦抽取在 2 段隔离测试里很好,接到真实 20 段池上假冲突 **+38.3pp**
(CI 完全不重叠),gold 碎裂 88%。**池结构才是破点。**
**检查:** 任何在隔离构造上取得的收益,进系统前必须在真实池上复测。**合成孪生训练出来的模型
同样受这条约束** —— 标签来自 mutation log 不等于能迁移。

**6. 收益是不是同一个来源被数了多次?**
事故:S8 —— 93% 的窗口含同 Wikipedia 条目的重复,虚增上界 0.328(415 题)。
实测兑现 **4 题**,两轴皆 null。**虚增统计上普遍、因果上惰性。**
**检查:** 报 `collision_rate`;结构性统计量**只能界定机会,不能预测效应**,两者可能差两个数量级。

**7. 两臂是不是在同一次运行里产生的?**
事故:跨运行比较在本项目造成过两次混杂,G6 因此把四臂放进同一个作业。
另有一次实测的跨作业漂移 0.021,**那是漂移不是结果**。
**检查:** 能同作业就同作业;不能就报出两次运行的 commit / 树指纹
(slurm 现在会打印 `[tree] <rev-parse HEAD>`)。

**8. train / dev / sealed 是不是真的不相交?**
事故:A4(2026-08-09)—— 适配池与 dev 评测运行相交 **202/2000**,而 `split` 标签
三个目录全写着 `dev`、**从来没真正划分过**。
**检查:** 按 **query_id + source_parent_id + synthetic_family** 三轴比**集合**,永远不读 `split` 标签。
`n_unresolved` 必须为 0 —— 有未解析文档时自 parent 回退会让零重叠比较**必然通过**。

## 用法

BEFORE 里逐条写一行"本轮如何排除",**排除不了的写明"本轮不排除,故本结论限于……"**。
八条全写"不适用"的实验,基本可以确定预注册没做认真。

AFTER 里把 `classify()` 的 tier 与 reasons 原样贴进去,不要改写成散文。
