## 1. Why this phase (context in four sentences)

The certified spine is done: diagnostic (ranking >> recall), raiser (Query2Doc +0.070,
p=0.0002), scale curve (10k -> 5M), and our novel Corroboration Reranking (+0.037,
nested-CV p~0.03). Three criticisms remain: (a) all NIAH findings rest on **one task
instance** (NQ/dpr-w100, one 300-query batch); (b) the corroboration gain is
**top-10-boundary-specific** (MRR flat — measured, p=0.94/0.81); (c) versus production
systems we look **expensive** (q2d = 1 LLM call/query, corroboration ~20 extractions)
and **small-scale** (5M fp32 ceiling). This phase closes (a) with replications, turns
(b) into a mechanism story, and turns (c) into a cost-quality curve + a 21M IVFPQ run.
Everything lands as a table/figure in `docs/results-summary.md` — the report (50% of
the mark) is written from there starting 08-03, no exceptions.

### WS-1a — TriviaQA haystack replication (answers "one task instance")
- **Goal:** rebuild the NIAH task with the SAME recipe on `dpr-w100/trivia-qa/dev`
  (300 queries; query/answer/needle/distractor distribution all change; corpus stays).
- **Steps:** `eval/build_niah_task.py` with the TriviaQA split -> freeze the task JSON
  under `results/` -> run three arms (`granite_dense`, `q2d_granite`,
  `q2d_corroborate`) via `eval/run_niah.py` -> significance vs dense and vs q2d.
- **Pass looks like:** diagnostic shape (ranking >> recall), q2d gain, corroboration
  gain all reproduce in sign (magnitudes may differ — report them honestly).
- **Report target:** "Robustness" subsection + one table. This is the single highest-
  value experiment of the phase.

### WS-1b — Fresh-seed NQ confirmation (kills the last tuning caveat)
- **Goal:** pre-registered confirmation of THE reported method — the **global convex
  blend, alpha=0.6, frozen**. (Finding 15: global == gated under CV, so the global
  blend is the method; the gated arm may be computed as a free secondary from the same
  runs, but it is never the headline.) NEW disjoint 300 NQ queries, new seed, run ONCE.
- **Steps:** build task (disjoint qid filter vs `niah_nq300_frozen.json`) -> run dense
  / q2d / q2d_corroborate (global, alpha=0.6) -> significance. No tuning of any kind.
- **Report line if it passes:** "the effect replicates on unseen queries with all
  hyper-parameters frozen in advance." If it fails: report as-is; finding 15 keeps
  the nested-CV caveat wording.

### WS-2 — Burial attribution (mechanism evidence, zero GPU)
- **Goal:** for every miss, WHO outranks the needle — counterfactual (cf), generative
  (gen), mined, or natural gold? The recipe JSON stores every distractor's doc_id +
  source; runs come from WS-0 dumps.
- **Prediction to test:** corroboration's gain concentrates on cf-buried queries
  (lone wrong-entity passages that relevance cannot demote). If the gain sits where
  the mechanism predicts, that is stronger evidence than more queries.
- **Deliverable:** per-source burial table + 2-3 case studies (needle vs the cf that
  beat it, before/after corroboration).

### WS-3 — Rank migration + found@k curves (defuses "boundary artifact")
- **Goal:** show WHERE q2d and corroboration act: found@k for k in {1,3,5,10,20,50,100},
  needle-rank CDF, and a before/after rank-migration matrix (dense->q2d from WS-0
  dumps; q2d->corroborate from the existing corroboration dump).
- **Story we expect the data to tell:** gains = buried (11-100) pulled into top-10,
  head order untouched — which is exactly the diagnostic's 0.44 buried mass, and why
  MRR stays flat. Also report @5/@10/@20 side by side (k-sensitivity).
- **Deliverable:** 2 figures + 1 table; feeds P7.

### WS-4 — Confidence-gated escalation cascade (the cost answer, zero GPU)
- **Goal:** simulate offline: if the dense margin (top1-top2, min-max normalised —
  `eval/gate_corroboration.py::margin_signal`) >= tau, keep dense; else escalate to
  q2d (and optionally + corroborate). Sweep tau -> curve of needle-found@10 vs
  fraction of queries that touched the LLM.
- **Framing:** Adaptive-RAG-style complexity routing (Jeong et al. 2024,
  arXiv:2403.14403), instantiated with a retrieval-native margin signal and certified
  stats. Answers "your winning stack is too expensive for production" with
  "cost scales with query difficulty; X% of queries never pay the LLM."
- **Deliverable:** cost-quality curve CSV + figure; efficiency table row for P7.

### WS-5 — Oracle headroom decomposition (owns the "39% still missed", zero GPU)
- **Goal:** three upper bounds from WS-0 dumps: (i) perfect-reranker bound = pool
  recall@100 (0.87 at 245k) — no reranker can beat it; (ii) oracle routing bound =
  per-query best of dense/q2d; (iii) pool-union recall — does q2d bring NEW needles
  into the top-100 pool, or only re-rank ones already there?
- **Deliverable:** one table splitting remaining error into ranking headroom (~0.26)
  vs recall headroom (~0.13) + the finding sentence "what research direction the
  remaining error actually needs."
- **Promoted (gates WS-14):** run FIRST — the ranking-vs-recall split decides whether the
  WS-14 fine-tune is worth the GPU (measure before you invest). **Prereq:** WS-0's
  `run_niah --dump-runs` dense + q2d full top-100 rankings; the corroboration dump
  (`nq300cert.json`) only carries the top-20 q2d pool — not enough for R@100 / oracle routing.

### WS-6 — Natural-pipeline transfer (external validity, cheap)
- **Goal:** run `q2d_granite` and `q2d_corroborate` on the EXISTING natural NQ +
  TriviaQA retrieval/RAG pipeline (~1M docs, cached indexes; add the presets to
  `eval/run_benchmark.py` if not yet exposed — reuse the `run_niah` stack factories).
- **Honest expectation:** q2d small gain; corroboration ~no gain, no harm (no planted
  counterfactuals). Frame: "designed for conflicting-evidence regimes; safe where
  conflicts are absent."

### WS-7 — Semantic vote matching (method upgrade, offline, timeboxed)
- **Tempered expectations:** the 8B re-extraction did NOT help (nested-CV +0.013 ns
  vs 3B's +0.037 — finding 15 note), so cleaner *extraction* is not the bottleneck.
  Matching is a different axis (vote aggregation), so one timeboxed attempt is
  justified — with modest expectations.
- **Step 0 — diagnose before building (the kill-switch):** from the first raw-answer
  dump (WS-0 format), measure vote-splitting directly: how often do valid answers for
  the same query differ only by alias/verbosity ("JFK" vs "John F. Kennedy")? If
  splitting is rare, STOP — matching has no headroom; write the sentence, move on.
- **Goal (only if Step 0 shows headroom):** alias/fuzzy matching in
  `src/retrieval/corroboration.py`; replay offline; re-run nested-CV.
- **Guardrails:** the match threshold is a NEW hyper-parameter — tune it only inside
  nested-CV folds, never on the full set. Start with token-overlap; embedding
  similarity merges over-eagerly and can hurt.
- **Timebox:** 1 week total including Step 0. No improvement — one honest sentence.

### WS-8 — Hybrid arm in the NIAH stack

- **Why:** production stacks are hybrid-by-default; we proved convex+SPLADE helps on

- **Promoted (parallel portfolio):** the *recall* arm of the A/B/D parallel push — bites the

### WS-9 — IVFPQ toward 21M (the "enterprise-scale" claim — de-risked)
- **The real cost is EMBEDDING, not indexing.** IVFPQ compresses the index; every
  passage must still be embedded first. Only ~5M embeddings exist — inside the cached
  flat index, so **recover them via faiss `reconstruct`, do NOT re-embed** — the
  remaining ~16M are unpaid GPU work.
- **Step 0 (W1, before committing to a target):** throughput probe — embed 100k
  passages on the A100 slice, measure passages/sec, extrapolate the 16M wall-clock.
  Pick the target from that number, not from hope.
- **Pipeline:** sharded + checkpointed embedding (batch -> disk shard -> resume) so
  walltime limits cannot lose work; train IVFPQ on a sample, then `add()` per shard.
- **Targets:** 10M = committed milestone; **21M = stretch**. Either yields the
  recall-vs-compression figure; the report says "demonstrated at X, method scales".
- **Priority rule:** background job only — it must never block WS-1a/1b/6/8/10 slurm
  slots. Under contention, the spine runs and offline workstreams win.

### WS-14 — Embedder hard-negative fine-tuning (the representation fix — STRETCH, high-risk)
- **Why it's new + where it sits:** every WS above hardens what we HAVE; this is the one bet on
  a *bigger* result — fixing near-duplicate burial at the representation source (findings 12/18:
  relevance rerankers and corroboration only modestly dent the ~0.26 ranking headroom). Fine-tune
  `granite-embedding-english-r2` with the counterfactual as an explicit hard negative, so the
  dense first stage itself separates the needle from its entity-swapped near-dup — which, unlike a
  reranker, can also move MRR.
- **Data (decided):** hard negatives via Longpre-style entity substitution (arXiv:2109.05052), NOT
  the `str.replace` Source-A (avoids the logical-seam artifact): same-type wrong-entity **corpus
  substitution** (MVP — sample from the dataset's answer set, no external deps) + **popularity-
  controlled** substitution (stretch). Alias substitution is a *correct* paraphrase → optional
  positive augmentation, never a negative.
- **Rigor gate:** training queries MUST be disjoint from the frozen 300q eval set — no
  train-on-test. Success = fine-tuned dense first stage beats baseline dense (0.493) and, the real
  win, q2d (0.563) on needle-found@10 + MRR (frozen 300q, `eval.significance`); ablate ± q2d /
  ± corroboration to see if it composes or overlaps. Validity check: train on corpus/popularity
  substitutions, test generalisation on the frozen task's `str.replace` Source-A it never trained on.
- **Gating / risk:** long-pole background only — never displaces the spine (WS-1a/1b/10) or the
  report for GPU. **Gated on WS-5:** if the oracle shows little reachable ranking headroom, scope
  down or drop. If it doesn't certify by **08-03 it is Future Work, not a headline**.
- **Needs a spec first:** `docs/superpowers/specs/2026-07-08-embedder-hardneg-finetune-design.md`
  (in progress); owner TBD.
