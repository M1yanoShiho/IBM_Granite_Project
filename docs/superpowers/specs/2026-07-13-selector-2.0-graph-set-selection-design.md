## 1. Problem — 为什么重开(1.0 验尸报告)

**1.0 是什么 [共识]**:固定 q2d top-20 池上的学习式 pointwise 重排器(LGBMRanker,
lambdarank,top-10 截断)——"带机器学习权重的投票 reranker"。

**1.0 证明了什么 [共识]**:域内(sealed NIAH)排序质量与正确证据保留显著优于固定权重
(NDCG +0.0206、Required Recall +0.0368,vs `fixed_0.6`);全部增量由投票特征承载
(去投票消融 `ml_relevance_rank` = q2d 基线,一分不涨)。

**1.0 败在哪 [共识]**:Harmful@10 不降(−0.0017,门槛 −0.02)→ Gate 1 FAIL;
ContractNLI 迁移显著负(−0.134)→ Gate 2 FAIL。

**机理诊断 [共识,支撑"重开"的动机]**:
1. **目标函数对 harmful 盲**——lambdarank gain [0,1,3,7,15] 中 utility-0 的 gain=0,
   把毒证据从第 8 名压到第 11 名几乎没有梯度,模型没有降毒动机;
2. **冲突结构缺席**——pairwise `supports|contradicts` 关系表(1.0 计划 §7.1)设计了、
   从未填充,模型看不见"谁和谁打架";
3. **相关性特征保护毒证据**——counterfactual 靠近满分相关性存活
   (`ml_full_no_relevance` 消融:去掉相关性,harmful 降到全场最低 0.0557,代价 NDCG −0.06)。

## 2. Core idea [共识]

架构上**重开**,不继承 1.0 的打分-排序-截断范式:

1. **建图**:池内候选为节点,**候选↔候选**连边(不再是查询↔候选):
   - 支持边:两条候选支撑同一答案;
   - 冲突边:两条候选不能同时为真;
   - 孤立节点:与池内其他证据无关系。
2. **集合选择**:不给候选独立打分排序,而是**整体选一个子集**,图结构作目标与约束——
   集合内部不许有冲突边、互相支持的边越多越好、覆盖问题所需全部条件、够了就停
   (**数量可变**);证据不足时输出 `insufficient` + `missing_facts`。

**关键性质 [共识]**:一条候选的价值取决于已选了谁(冗余降值、冲突负值)——目标不可分解为
独立分数,故数学上不是排序。

**为什么这个重开瞄得准 [P6 输入,owner 未反对]**:"集合内部不许有冲突边"这个约束,等价于
在集合内部给 harmful 无穷大惩罚——恰好补上 §1 诊断 1;边本身就是 §1 诊断 2 缺失的冲突结构。

**术语裁定 [共识,2026-07-13 聊天确认]**:"支持边(两条候选说同一个答案)"的判定 = 抽取
各候选答案后做匹配 = **投票信号的图形式**(一致图中节点度数 = vote count)。因此 2.0
**不是去除投票信号,而是把它从标量特征升级为图的边**;1.0/corroboration 已认证的
抽取+归一化+匹配管道(`src/retrieval/corroboration.py` 的 `normalize_answer`/
`is_valid_answer` 一族)是支持边的现成实现。架构重开,信号管道延用。

## 3. 三个必答题 [必答题 — spec 定稿的核心内容]

### ① 边用什么计算

| 候选方案 | 性质 | 已知风险/依据 |
|---|---|---|
| 抽取答案一致(支持边) | 投票的图形式,管道现成、已认证 | 抽取失败即缺边;别名分裂(WS-7 语义匹配可补) |
| NLI 蕴含/矛盾(小型 MNLI cross-encoder,成对) | **真正的新信息**——能抓改写过的冲突、抽取漏掉的矛盾 | 句子级训练的模型对 100 词段落偏噪;O(k²) 成本(k=20 → 190 对,小模型可承受);新依赖+阈值 |
| 文本/向量相似度 | 文献有先例(GRADA,EMNLP 2025,图上 PageRank 降权孤立文档) | **[P6 输入] 预测在本病理上失效**:近重复 counterfactual 与真证据几乎同文,在相似度图里是全图最强边——毒证据"最合群"而非孤立。GRADA 防注入怪文本,防不了单实体改写。可用零成本预检验证(§7) |

建议 [P6 输入]:边定义写成**内置消融**(agreement / NLI / similarity 三臂),让数据裁决。

### ② 仲裁规则——冲突 ≠ 有害

冲突边只说明"有人错了",不说明"谁错了"(1.0 计划原句:"两条候选互相冲突时,不能自动把
双方都标成有害")。图上两个阵营对峙时选哪边,必须有显式仲裁信号:多数支持(=投票)、
parametric 一致、来源质量/metadata(时间、版本、公司)。**若仲裁 = 多数支持,投票再次
成为承重件**——需在 spec 中明写,避免"重开=不需要投票"的误读。

### ③ 法定基线——2.0 必须打赢 1.x 才立得住

同一候选池、同一生成预算下,集合选择 vs **已认证的排序截断路径**:
- 主线:dense→q2d→corroborate,needle-found@10 = 0.493→0.563→0.607(n=300 冻结任务);
- 1.0 自身:`fixed_0.6` 与 `ml_core/ml_full`(utility-NDCG 体系)。
赢了,复杂度才有理由;赢不了,如实报告——这本身是关于集合选择价值的可报告发现。

## 4. 范围边界 [共识,双方多轮确认]

1. **池边界不归 2.0 管**:"不排序、在一个堆里建图"适用于池内;那个"堆"仍是上游检索+查询
   改写排出来的 top-20。needle 不进池,任何选择器救不回(R@100=0.87,13% 不可达)。
   2.0 不解除对上游排序质量的依赖,也不试图解决召回问题。
2. **序列化规则必须声明**:集合内部无序是选择目标的性质,不是管线的性质——证据最终按某个
   顺序进入生成器 prompt,而窗口/位置效应已被实测(finding 17:k=4 时增益反转)。spec 需
   写明交付顺序规则(哪怕是"按 doc_id"),不能留空。

## 5. 评估设计 [必答题,框架已共识]

数量可变 ⇒ NDCG@10 / needle-found@10 失效,换集合级指标:
- evidence-set precision / recall / F1(对官方证据集合);
- required-fact / condition 覆盖率;
- `insufficient` 判断的准确率(需要带 unanswerable 标注的正例);
- harmful-in-set 率(受控测试床上,毒证据进最终集合的比例——2.0 版 Gate 1 主指标)。

**数据前提**:证据集合标注(supporting-facts 式)+ 不可回答标注 = 数据集需求清单的
缺口①③(候选:HotpotQA/2Wiki/MuSiQue、ConditionalQA;用前逐一核实)。

**测试床**:滤毒能力的度量需要**已知有毒**的候选做 ground truth——受控注入
(`src/niah/` 构造管线)是唯一带该标签的测试床;1.0 的 sealed 池构造(实体替换 + 盲测换
模板)同族。此为"注入基础设施保留为评估仪器"决策的直接依据。自然冲突域
(RAMDocs 官方 misinfo 标签、FinanceBench metadata 规则)作生态效度补充,两者互补。

**纪律延用 1.0 全套**(它是 1.0 做得最好的部分):协议冻结 → 封闭切分(父页面/合同/公司
分组防泄漏)→ 阴性对照(shuffled-label / shuffled-edge)→ 预注册 Gate + 停止规则。
2.0 版 Gate 草案:Gate 1 = 受控床上 harmful-in-set 显著低于 1.x 基线且 required 覆盖非劣;
Gate 2 = ≥2 个外部域非劣/正向;Gate 3 = 答案端(集合喂给 Generator 的 cover-EM/F1/引用)。

## 7. Risks & honest limitations

1. **相似度边陷阱**(§3①)——若 owner 坚持相似度边,先跑预检,预测为负;
2. **仲裁缺席风险**——只有冲突结构没有仲裁,图会退化为"删掉所有打架的",孤立真针
   (旧 corroboration 的孤证问题)会被误伤:required 覆盖非劣界必须进 Gate;
3. **NLI 段落噪声**——句子级模型上段落要先取关键句,增加管线复杂度;
4. **组合搜索成本**——k=20 的子集空间大,需贪心/约束求解等近似,spec 应声明算法而非枚举;
5. **novelty 定位(诚实)**:图结构(GRADA/FEVER 系)、集合选择(MMR/submodular)、冲突
   处理(MADAM-RAG)各有先例;可辩护槽位 = **冲突结构图 + 互证仲裁的集合选择,在近重复
   反事实病理上的受控验证**。不得表述为"解决了误导证据问题"。
